# ASCL-S5-002 · 经济交易、配方与资源预留

## 问题与预期收益

当前基线尚未完成本目标的正式验收。通过经济交易、配方与资源预留沉淀可跨项目复用、可观察和可验证的能力。

## 工作内容与边界

- **D10-C08 经济交易**：货币、买卖、兑换、合成消耗及失败回退；完整提交不等同于数值通知合并。
- **D12-C02 配方与生产**：输入输出、生产时间、队列和暂停。
- **D12-C03 资源预留**：记录已分配但尚未搬运交付的数量，防止重复占用。

只实现本目标列明能力并提供最小完整示例；跨模块需求通过显式依赖接入，不提前实施其他目标。

## 交付物

- 可安装或可组合的规则实现／适配，以及最小完整使用示例。
- 与目标相符的验证结果、支持矩阵、错误诊断和必要迁移说明。

## 公共接口与兼容

事务式资源操作、配方、生产队列和预留身份；不同于 Numeric 通知批量合并。

遵循 PLAN.md 的身份、生命周期、模拟、内容版本与后端能力边界。稳定接口破坏性变更提供迁移路径；未测试平台不标为支持。

## 验收条件

- [ ] 合成的扣材料/货币/产物一致提交
- [ ] 容量不足和中途失败不丢失资源
- [ ] 预留不能被重复消费。
- [ ] 交付与验证证据已写入元数据 evidence，实际验证记录写入 log。

## 验证场景

合成的扣材料/货币/产物一致提交；容量不足和中途失败不丢失资源；预留不能被重复消费。

提供正常路径与相关失败、取消、重复和恢复路径的可重复样例。先 .NET/Unity 桌面，IL2CPP/移动端在对应目标验证。
